# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `GET /health` | Returned static `{"status": "ok"}` without testing database connectivity. | Stop MongoDB or pass invalid URI; endpoint still returned 200 OK instead of 503. | Added `db.command("ping")` inside a try-catch block, raising HTTPException 503 on failure. |
| 2 | Startup / Indexes | No indexes were created at startup; duplicate records could be created concurrently. | Running concurrent punch-ins for the same employee and date created multiple documents. | Added idempotent startup index creation: unique `emp_code` on employees, unique compound `(emp_code, date)` on attendance_logs. |
| 3 | API Boundary serialization | MongoDB internal `_id` (BSON ObjectId) and BSON datetimes leaked in API responses. | Client received `_id: "..."` and raw ISO strings rather than integer epoch milliseconds. | Implemented `serialize_employee` and `serialize_attendance` to strip `_id` and convert instants to epoch ms ints. |
| 4 | `POST /employees` | Missing validation for shift times and joined_on; duplicate `emp_code` caused unhandled 500 server crash. | Sending invalid shift format `9:30` or identical start/end returned 200; duplicate code crashed. | Added regex validation for `HH:MM` and `YYYY-MM-DD`, checked `shift_start != shift_end`, and caught `DuplicateKeyError` to return 409. |
| 5 | `GET /employees` | Pagination skipped the wrong number of rows (`page * page_size`), total counted all docs instead of filtered docs, no sort order. | Requesting `page=1` skipped the first page of results; total remained collection total when filtering by department. | Changed offset to `(page - 1) * page_size`, filtered `count_documents(q)`, and added `sort("emp_code", ASCENDING)`. |
| 6 | `POST /attendance/punch-in` | Did not verify employee existence (404); accepted `ABSENT`/`LEAVE`; wrong overnight shift date; subtracted grace period from late minutes. | Unknown employee got 201; punch at 09:40:01 IST gave 1 late minute instead of 10. | Added employee lookup (404), restricted status to presence, resolved overnight shift date per R1, and calculated full minutes since shift start per R2. |
| 7 | `GET /attendance` | Allowed `date_from > date_to`; sorting was arbitrary; nested history datetimes were unformatted. | Query with `date_from=2026-07-10&date_to=2026-07-01` returned empty list 200 instead of 422. | Added `date_from <= date_to` validation (422), sorted `date DESC, emp_code ASC`, and converted nested history timestamps. |
| 8 | `GET /admin/explain/{endpoint}` | Explain endpoints returned default queryPlanner instead of executionStats and used abbreviated or mismatched aggregation pipelines. | Missing execution statistics in explain output; department filters and window functions omitted. | Configured `verbosity="executionStats"` on `db.command("explain", ...)` and shared exact pipeline builders across operational and explain endpoints. |
| 9 | `POST /attendance/punch-out` | Selected the latest punch-in record regardless of whether it occurred after `punched_at`. | An employee with a future punch-in could not close an older eligible open record. | Updated query to `{"emp_code": emp_code, "punch_in": {"$lte": punch_out_dt}}` sorted descending by `punch_in`. |
| 10 | `PATCH /attendance/{emp_code}/{date}` | Optimistic locking filtered on `{"history": {"$size": 0}}`, failing on documents where the `history` field was absent in seed data. | Regularizing a legacy document without a `history` field raised conflict or failed to update. | Updated filter to `{"$or": [{"history": {"$exists": False}}, {"history": None}, {"history": {"$size": 0}}]}` for empty history. |
| 11 | `GET /analytics/departments/{department}/trend` | `$densify` produced 0 output documents when a department had 0 attendance records in the entire requested date range. | Trend query for a valid department with no logs in the date range returned an empty list instead of densified calendar days. | Added `$unionWith` stage seeding 1 document for the department to ensure `$densify` generates every calendar day in MongoDB. |
| 12 | `POST /employees` | Pydantic schema lacked OpenAPI constraint annotations for `emp_code` regex pattern, `name`/`department` length limits, and `email` format. | Invalid employee codes like `EMP1` or malformed emails were accepted. | Added `Field(...)` constraints matching `EmployeeCreate` in `openapi.yaml`. |
| 13 | R5 Half-Day Rule | Half-day calculation threshold was `< 4.0` hours instead of `< 4.50` hours per business rule R5. | An employee with 4.25 work hours was marked full day instead of half-day. | Updated threshold in `compute_half_day` to `< 4.50` and verified half-day contributes 0.5 to analytics. |
| 14 | `GET /admin/explain/department_trend` | Unsorted `{"$limit": 1}` inside the `$unionWith` stage on `employees` caused MongoDB to plan a `COLLSCAN` on the employees collection. | Explain output for `department_trend` contained `COLLSCAN` alongside `IXSCAN`. | Added `{"$sort": {"emp_code": 1}}` prior to `{"$limit": 1}` so MongoDB utilizes the unique `emp_code` index (`IXSCAN`), eliminating `COLLSCAN`. |

### Things inspected and confirmed NOT to be defects:
1. **PyMongo naive datetimes**: PyMongo returns datetimes without tzinfo by default. Per `DATA_MODEL.md`, treating naive datetimes as UTC and converting explicitly at the boundary is the standard design.
2. **`emp_code` string format**: `emp_code` is customer-generated alphanumeric string (e.g. `EMP0001`), not an ObjectId or integer.
3. **No automatic record generation for non-punched days**: Weekdays with no attendance records are not stored as `ABSENT`; days simply have no document, which is handled via `$densify` in trends.
